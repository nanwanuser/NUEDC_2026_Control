# 视觉二进制串口协议

USART1配置为115200、8位数据、1位停止位、无校验。所有多字节整数使用小端序，
坐标使用有符号16位整数表示，单位为0.1 mm。

## 坐标系约定

视觉上报的坐标必须与塔吊控制层的世界坐标系一致，即 `Task/crane_control`
定义的那一个：横放 A4 纸**左上角**为原点，沿长边**向右**为 `+X`（`0..297`），
沿短边**向下**为 `+Y`（`0..210`），单位 mm。以 `crane_control_config.c` 为准。
决策层直接在这个坐标系里求解并输出摆放位置，中间不做任何坐标变换，因此视觉端
换错坐标系不会报错，只会让机构走到错误的位置。

碎片摆在左半侧（`x < 148.5`），拼装在右半侧（`x > 148.5`），对应题目竖放时的
上下半侧。决策层在搜索之前就检查这一点：任何碎片中心落在 `x >= 148.5` 都会直接
返回 `DECISION_RESULT_WRONG_HALF`，因为那通常意味着视觉端用错了坐标系，而不是
几何问题。

`int16` 加 0.1 mm 量化使单轴范围为 `-3276.8..3276.7 mm`，A4 幅面远在其内。

## 视觉结果帧

```text
AA 55 | version | type | seq | payload_length | payload | crc16 | 0D 0A
 2 B  |   1 B   | 1 B  | 2 B |      2 B       |  N B    |  2 B  |  2 B
```

- `version`：固定为`0x01`。
- `type`：视觉结果为`0x01`。
- `seq`：`uint16_t`循环序号。
- `payload_length`：只包含payload。
- `crc16`：CRC16-CCITT-FALSE，多项式`0x1021`、初值`0xFFFF`，计算范围从
  `version`到payload最后一个字节。
- 结束符：固定为`0x0D 0x0A`。

payload开头为：

```text
reserved      uint8_t  // 原decision_mode，接收端忽略，填0即可
piece_count   uint8_t  // 1..4
```

之后连续放置`piece_count`块碎片。每块格式为：

```text
id             uint8_t
vertex_count   uint8_t  // 3..5
cx             int16_t
cy             int16_t
vertex[0].x    int16_t
vertex[0].y    int16_t
...
```

一块碎片长度为`6 + 4 * vertex_count`，4块、每块5顶点时完整帧最大118字节。
同一帧内ID不能重复，顶点必须沿轮廓依次排列。

## 稳定确认

STM32连续收到3个相近的有效帧才提交决策。碎片数量、ID和顶点数量必须完全相同，
中心和顶点坐标允许相差0.5 mm。比较时按ID匹配碎片，并自动处理顶点起点循环变化
和顺逆时针变化。最终坐标取3帧平均值。

确认后STM32立即停止接收并反初始化USART1，再调用`DecisionTask_Submit()`。
提交成功或失败都不会重新打开本轮接收窗口；下一次武装时才重新初始化USART1并
接收最新数据。链路不使用ACK。

## 视觉模式命令

STM32在每次武装后通过同一USART1向MaixCAM发送控制帧。外层格式、CRC和帧尾与
视觉结果帧相同，`type=0x80`、`payload_length=1`：payload为`0x01`时只请求几何
结果，为`0x02`时只请求扑克牌花纹结果。

接收器先启动，模式命令随后发送；在收到目标类型的第一个有效帧或卡牌分片前，
STM32每100ms重发一次，单轮最多5次。MaixCAM未收到有效模式命令前不发送结果，
模式变化时必须丢弃上一模式冻结的数据。损坏或未知命令不改变MaixCAM当前模式。

## 采集授权

STM32视觉任务上电后不主动接收，`VisionUart_Arm()`被调用才打开接收器。题目要求先
遮挡摄像头摆放碎片、按键启动时同时移除遮挡，因此启动键之前到达的帧会被丢弃。

每次`VisionUart_Arm()`会在必要时重新初始化USART1，所以一轮提交后仍可再次武装，
反复测试不需要重新上电。`VisionUart_Abort()`放弃当前采集。
