# 真实扑克牌四等分仿真设计

## 目标

在现有主机仿真中新增 `card` 场景：使用一张真实扑克牌位图，将其沿中心横线和中心竖线四等分，打乱四个矩形牌片后调用固件真实的 `Decision_SolveCard()`，验证花纹策略能恢复正确牌面，而不只是拼出任意矩形。

## 范围

- 保留现有 `general` 几何场景及其默认行为。
- 新场景使用 `100 x 70 mm` 牌面，四片均为 `50 x 35 mm`。
- 使用仓库内固定 PNG 资产，确保离线运行和结果可重复；命令行允许传入另一张本地图片用于复测。
- 仿真直接加载 `decision.c` 和 `trajectory.c` 编译出的动态库，不在 Python 中重写拼图算法。
- 本轮验证策略与运动仿真，不模拟相机畸变、照明变化或 MaixCAM 标定误差。

## 数据流

1. 读取牌面 PNG，统一缩放到固定像素尺寸。
2. 沿图像中心横、竖切线分成左上、右上、右下、左下四块。
3. 对每条真实内部切缝，在切线两侧窄带中分类红色和黑色像素，合并连续像素段。
4. 仅当同一连续段在切线两侧都有像素证据时，为相邻两片生成成对 `DecisionCardEdgeEvent`；位置按各片边长量化为 `position_q8`，颜色、方向、宽度和置信度使用与固件数据模型相同的单位。
5. 从每片内部较大的红/黑连通域提取少量 `DecisionCardPrimitive`，作为边缘事件不足时的辅助证据。
6. 将四片按固定角度和平移量散布到 A4 左半区，几何顶点、中心、事件和基元保持同一坐标系。
7. 通过 `ctypes` 调用 `Decision_SolveCard()`，再沿用现有轨迹生成和采样流程。
8. 可视化层把四张真实纹理贴到运动中的牌片上，并显示原始牌面、最终拼接、搜索节点数与接缝误差。

## 结构修改

### `simulation/bindings.py`

- 同步固件的卡牌颜色、事件、基元、逐片特征和 `DecisionCardFrame` 结构。
- 同步 `DecisionPlan.search_nodes`，并绑定 `Decision_SolveCard()`。
- 扩展 native bridge 的尺寸与字段偏移检查，防止 Python/C ABI 静默错位。

### `simulation/card_image.py`

- 负责图片加载、固定四等分、红黑分类、切缝连续段提取和内部基元提取。
- 输出独立于 Matplotlib 的纯数据对象，便于测试。

### `simulation/scenarios.py`

- `create_scenario("general")` 保持原状。
- `create_scenario("card", card_image=...)` 创建卡牌帧、纹理元数据和预期拓扑。
- `solve_scenario()` 根据场景类型调用几何或卡牌固件入口。

### `simulation/visualization.py`

- 普通场景继续显示纯色多边形。
- 卡牌场景为每片显示对应位图纹理，并随抓取位姿进行平移和旋转。
- 最终状态旁显示 `search_nodes`、正确邻接检查和接缝像素误差。

### `simulation/main.py`

- 新增 `--scenario general|card`，默认仍为 `general`。
- 新增 `--card-image PATH`，只在 `card` 场景使用。
- `--snapshot` 保持无界面输出方式。

## 验收

- 绑定层结构尺寸和关键偏移与 C 一致。
- 真实牌面四条内部半接缝能生成成对的红/黑事件。
- `Decision_SolveCard()` 返回 `DECISION_RESULT_OK`，`move_count == 4`。
- 最终布局中原始对角片仍为对角关系，四条内部邻接均正确。
- 将最终布局归一到牌面坐标后，四块纹理能重建原图；接缝像素平均绝对误差低于测试阈值。
- `DecisionPlan.search_nodes` 小于场景预算并显示在结果中。
- `general` 场景的原有快照和轨迹行为不回归。
- 仿真可以生成一张最终 card 场景 PNG 快照。

## 失败处理

- 图片不存在、无法解码或尺寸过小：命令行返回非零并给出明确错误。
- 切线没有足够红/黑证据：场景构建失败，提示更换包含中心花纹的人头牌图片。
- 固件返回歧义、无解或搜索上限：仿真返回非零并打印结果码和已提取事件数量。
- ABI 不一致：加载动态库时立即失败，不进入仿真。

## 非实机结论

该仿真能验证“真实牌面切线产生的稀疏特征是否足以让 STM32 选择正确排列”，但不能替代现场验证。MaixCAM 阈值、反光、切割毛边、串口稳定性和机械落位误差仍需实机测试。
