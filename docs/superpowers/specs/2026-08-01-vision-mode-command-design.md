# STM32到MaixCAM视觉模式命令设计

## 目标

按下Key1时，STM32明确要求MaixCAM发送几何结果；按下Key2时，明确要求
MaixCAM切换到扑克牌花纹模式并发送卡牌分片。视觉算法持续运行，但在收到第一条
有效模式命令前不发送结果。

## 当前行为

现有MaixCAM代码在精测完成后持续上报，STM32仅在按键后打开接收窗口。因此现场
表现为“按键触发最新结果”，实际链路中不存在STM32到MaixCAM的控制数据。本设计
在已经双向连接的USART1和`/dev/ttyS0`上补齐控制方向。

## 控制帧

复用视觉协议的通用外层：

```text
AA 55 | version | type | seq | payload_length | payload | crc16 | 0D 0A
```

- `version = 0x01`
- `type = 0x80`，表示STM32到MaixCAM的模式命令
- `payload_length = 1`
- `payload[0] = 0x01`：几何模式
- `payload[0] = 0x02`：扑克牌花纹模式
- CRC算法和覆盖范围与视觉结果帧完全一致

损坏CRC、非法长度、未知模式和不完整帧均被MaixCAM忽略，不能改变当前模式。

## STM32状态流

`VisionUart_Arm()`仍只跨任务提交请求。Vision UART任务收到武装请求后重新初始化
USART1、启动Receive-to-idle，再发送与`DecisionStrategy`对应的模式帧。若尚未收到
目标类型数据，每100ms重发一次，单轮最多5次；收到第一个目标类型的有效帧或分片
后停止重发。接收、三帧稳定和决策提交逻辑保持不变。

## MaixCAM状态流

`VisionUartPublisher`打开UART后，每次主循环先非阻塞读取控制数据。初始模式为
`None`，此时只识别和缓存现场状态，不上报。收到有效模式后：

- 几何模式只冻结几何结果并重复发送`type=0x01`。
- 扑克牌模式才运行花纹提取，只重复发送`type=0x02`卡牌分片。
- 模式变化会清空旧模式的冻结结果、分片索引和发送节拍，下一次发布从当前最新
  精测结果重新构建。
- 重复收到相同模式是幂等操作，并允许立即重发当前冻结结果。

## 失败处理

STM32模式帧发送失败不立即结束任务，由有限重试覆盖瞬时忙状态；最终仍无目标视觉
数据时沿用任务采集超时。MaixCAM读取异常不停止视觉，写入异常沿用现有禁用发送
逻辑。两端无需ACK，避免恢复已经删除的提交握手状态机。

## 验证

- C测试验证模式帧字段、CRC、非法策略和容量不足。
- Python测试验证噪声、分片输入、CRC错误、未知模式和连续多帧解析。
- Publisher测试验证未选模式不发送、几何模式不提取卡牌特征、卡牌模式只发分片、
  模式切换清除旧结果。
- 运行MaixCAM pytest、STM32协议/决策测试和Debug固件构建。
