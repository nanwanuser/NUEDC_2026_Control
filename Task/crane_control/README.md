# 塔吊末端控制

本模块连接 `Task/route_planning` 与执行器驱动。规划器提供世界坐标系中的
`x_mm`、`y_mm`、`z_mm`、`yaw_deg` 和 `grip`，控制层只保留最新样本并以
20 ms 周期更新执行器，避免路径点排队造成滞后。

## 坐标定义

`CraneControlConfig.origin` 是塔吊局部坐标系在世界坐标系中的原点：

- `origin.x_mm`、`origin.y_mm`：塔吊回转中心的世界坐标。
- `origin.z_mm`：升降软件零位的世界高度；本装置取行程上端，见「当前实测配置」。
- `origin.yaw_deg`：吊臂机械零方向在世界坐标系中的角度。

控制层执行以下变换：

```text
dx = x - origin.x
dy = y - origin.y
radius = sqrt(dx^2 + dy^2)
boom_yaw = atan2(dy, dx) - origin.yaw
z_local = z - origin.z
```

规划器的 `yaw_deg` 按世界坐标解释。末端 Yaw 舵机自动减去当前吊臂的世界
方向，因此吊臂回转时，末端仍尽量保持规划器指定的世界朝向。

## 初始坐标与标定

默认配置由 `CraneControl_LoadDefaultConfig()` 生成。可在任意项目源文件中
覆盖弱函数，在控制任务启动前修改原点及机械参数：

```c
void CraneControl_CustomizeConfig(CraneControlConfig *config)
{
    config->origin.x_mm = 120.0f;
    config->origin.y_mm = 80.0f;
    config->origin.z_mm = 35.0f;
    config->origin.yaw_deg = 90.0f;

    config->reach_zero_radius_mm = 45.0f;
    config->min_radius_mm = 45.0f;
    config->max_radius_mm = 145.0f;
}
```

默认按 M1、Z30 齿轮计算：每转行程为 `pi * 30 = 94.2478 mm`。伸缩轴使用
`reach_mm_per_motor_revolution`，升降轴使用
`lift_mm_per_degree = 94.2478 / 360`。实际机构若有减速级、不同有效分度圆或
安装偏差，必须按实测结果修改；四个 `*_direction_sign` 用于反转机械方向。

## 执行器与限制

- PD42S1 地址 1：塔身/吊臂 Yaw，使用相对位置模式。
- PD42S1 地址 2：齿条伸缩，使用相对位置模式。
- 规划器目标仍是绝对位姿；控制器记录最近一次成功接受的软件目标，并向驱动器
  发送新旧目标之差。
- MG996R 舵机 1：升降；舵机 2：末端电磁铁 Yaw，均限制为 0–180°。
- `min/max_boom_yaw_deg`、`min/max_radius_mm` 和 `min/max_z_mm` 是软件工作空间。
- 超出工作空间的整组目标会被拒绝，状态为 `CRANE_CONTROL_OUT_OF_WORKSPACE`。

两轴上电后用力矩模式顶到机械硬限位，把硬限位作为软件与驱动器共同的零位，见
「启动力矩顶零与基准」。电磁铁由 PE12 经继电器驱动，`crane_control_config.c` 覆盖了
弱函数 `CraneControl_SetMagnet()`。舵机没有位置反馈，状态中的角度是软件输出角度，
不是实际测量值。

## 当前实测配置

世界坐标系就是视觉端的 A4 坐标系，全工程各层共用同一套：A4 横放，**左上角为
原点**，沿长边向右为 `+X`（`0..297`），沿短边向下为 `+Y`（`0..210`），竖直向上
为 `+Z`。`+Y` 向下使得从上方俯视时这是一个左手系，于是 `atan2(dy, dx)` 递增的
方向在纸面上就是**顺时针**——这正好是启动顶零转动吊臂的方向，所以视觉与机构之间
不需要任何符号翻转。

- 圆形底盘直径为 `100 mm`，与 A4 纸 `y = 0` 那条长边相切，中心对准长边中心。
- 回转中心：`(148.5, -50.0) mm`；即长边中点 `297/2 = 148.5 mm`、纸外 `50 mm`
  处，立柱位于 `y = 0` 长边之外。
- 电机零位吊臂指向 `+Y`，世界 Yaw 为 `90 deg`：从立柱跨过 `y = 0` 边指向纸的
  另一条长边。
- 回转传动比为 `1:1`，吊臂局部范围为 `-90..90 deg`。
- 启动顺时针顶零把 Yaw 轴硬限位定为局部 `+90 deg`。局部 `+90` 叠加 `+Y` 的零位
  朝向，世界 Yaw 为 `180 deg`，即指向 `-X`——归零后吊臂横跨纸面指向 `x = 0`，
  与机构实际表现一致。
- 伸缩零位半径为 `70 mm`，向外有效行程为 `160 mm`，半径范围为
  `70..230 mm`。
- 升降软件零位就是行程上端：舵机 `0 deg` 时实测电磁铁中心在纸面以上
  `40 mm`，因此 `origin.z_mm = 40 mm`，局部 Z 范围为 `-39..0 mm`，对应世界
  高度范围为 `1..40 mm`。上电停放高度取行程上端 `0 mm`，吸取深度为世界
  `1 mm`。舵机角增大对应下降，所以 `lift_direction_sign = -1`。
- M1/Z30 齿轮实测每转行程为 `94.2478 mm`；升降换算为
  `94.2478/360 mm/deg`。
- Yaw/伸缩速度分别为 `40/20 rpm`，加速度档位分别为 `10/5`。
- 方向符号依次为 Yaw `-1`、伸缩 `+1`、升降 `-1`、末端 Yaw `-1`。
- 两台 PD42S1 均开启命令应答，控制器等待并校验每条应答。

按升降舵机逻辑零角 `0 deg` 计算，当前 Z 边界对应的舵机角为
`0..149.0 deg`（`39 / 0.2618 = 149.0 deg`）；上电停放对应上端的 `0 deg`，吸取
对应 `149.0 deg`。`149.0 deg` 以外只剩 `31 deg`（约 `8 mm`）没有使用，行程已经
占掉舵机的六分之五，因此若电磁铁还要往下探，余量有限，应优先从机械上降低连杆，
而不是继续加深 `min_z_mm`；逻辑零角已经在舵机下限，不能再降。实机首次运行仍应
脱离负载，确认两端没有机械干涉。

末端 Yaw 不使用安装零偏。规划器世界 Yaw 减去吊臂世界方向后，得到末端
相对吊臂的 `-90..90 deg` 角度。反方向最大位置 `-90 deg` 作为机械零角；
在 `end_yaw_direction_sign = -1` 时，它对应舵机命令 `180 deg`。相对角从
`-90 deg` 增加到 `90 deg` 时，舵机命令从 `180 deg` 减小到 `0 deg`。
中心角保持 `90 deg`，安装零偏固定为 `0 deg`。

## 末端 Yaw 基准偏置

末端 Yaw 装在吊臂上，能保持的世界 Yaw 只有「吊臂方向 ± 90 deg」。决策层
按拼图几何选取世界 Yaw，并不知道这个限制，因此直接执行会有大量抓放点落在
末端行程之外。

真正决定拼图姿态的只是抓取点与摆放点之间的 Yaw *差值*，给同一次搬运的所有
路径点加上同一个常量不改变拼图结果，却能把末端拉回中位。
`CraneControl_ChooseYawBias()` 计算该常量：它取这组路径点所需末端角的中点，
使其对齐舵机中心角，并在跨 `±180 deg` 时先解卷绕。`Task/route_planning`
在生成轨迹前对每次搬运调用一次并整体施加。若整组所需角度的跨度超过舵机
`180 deg` 行程，则任何偏置都无法容纳，函数返回
`CRANE_CONTROL_OUT_OF_WORKSPACE`，同时仍写回尽力而为的偏置。

当前最大半径为 `230 mm`。塔吊中心 `(148.5, -50)` 到 A4 纸上侧两个角点的
距离约为 `299.5 mm`，因此机构不能覆盖整张 A4 纸。本装置采用半径限制方案：
规划和拼图输入必须位于塔吊中心半径 `70..230 mm` 之间，控制层仍会拒绝超出
该范围的目标。两轴的启动力矩顶零已启用，见「启动力矩顶零与基准」。

## 取放半区

抓取固定在 A4 左半侧（`x < 148.5`），摆放固定在右半侧（`x > 148.5`）。这是由
共用坐标系直接定下来的，不再从碎片落在哪一侧去推断：`App/lib/decision` 在搜索
之前就检查每个碎片中心，只要有一个落在 `x >= 148.5`，直接返回
`DECISION_RESULT_WRONG_HALF`，任务层报 `MISSION_RUN_DIAG_WRONG_HALF`。这类情况
不做兼容处理——要么纸摆反了，要么相机标定的原点角点不是本工程约定的左上角，两者
都得人工改。

`Decision_GetDefaultConfig()` 的默认目标中心取右半区中心 `(222.75, 105)`。
`Task/mission` 用自己的 `(210.5, 85.5)` 覆盖它，该点是按**回转余量**挑的，因为
这是真正的约束条件：题目最大的 `12x9 cm` 矩形，四个角在**两种摆向下**都必须落在
`70..230 mm` 半径带内（求解器最终横放还是竖放，任务层事先并不知道）。在
`(210.5, 85.5)` 处，两种摆向的最远角为 `r = 222.9 mm`、最近角为 `r = 77.4 mm`，
两端各约 `7 mm` 余量，是这半区内能取到的最大余量，同时矩形不越过中线、也不越出
纸的四条边。

## 供任务层查询的接口

任务层不应重复实现本模块的坐标定义，改用以下只读接口（均可在
`CraneControl_Init()` 之前调用，此时返回启动后将生效的配置）：

- `CraneControl_GetConfig()`：取得完整配置，含原点和工作空间边界。
- `CraneControl_GetPoseAt()`：把吊臂角度、半径、Z 换算为规划器位姿。
- `CraneControl_GetCurrentPose()`：取得最近一次执行的位姿；未初始化时返回
  启动停放位姿，可直接作为首条轨迹的起点。
- `CraneControl_CheckPose()`：只校验位姿是否落在吊臂、伸缩和末端行程内，
  不动作。`Task/route_planning` 在生成轨迹前用它逐点检查，把「机构中途
  停住」变成一次明确的规划失败。
- `CraneControl_PlanTransitPoses()`：见「最小半径与过渡点」。
- `CraneControl_ChooseYawBias()`：见「末端 Yaw 基准偏置」。

## 最小半径与过渡点

只检查路径点是不够的。轨迹在笛卡尔空间插值，两个都可达的点之间的直线段
仍然可能切进最小半径：大角度摆臂的弦比两端都更靠近立柱。启动停放位姿
`(78.5, -50)` 正好在 `70 mm` 圆上，从它出发的直线段几乎都会越界，机构会在
第一次搬运开始后的一瞬间拒绝参考值。

`CraneControl_PlanTransitPoses()` 为这样的段生成过渡点：在两端航向之间等分，
半径取一条使所有子段都留在 `70..230 mm` 内的圆弧。候选半径由内向外尝试，
因为五次样条会超过它所经过路径点的半径，圆弧鼓得比需要的更远只会把问题从
最小半径换成最大半径。每段最多插入 2 个点。

`Task/route_planning` 在生成轨迹前重建路径，逐段调用它，并把剩余
`TRAJECTORY_MAX_WAYPOINTS` 预算让给后面还要复制的点。段数放不下时直接
判为规划失败，而不是交给机构在运行中拒绝。

过渡点沿用段起点的 Z：升降是按 Z 变化的符号触发的两位舵机，这里改变高度会
多出两次无用行程。

用仿真里的原生库对 824 条路段（含停放点出发和网格点两两组合）做过采样验证：
样条实际半径范围 `70.00..230.00 mm`，吊臂 `-71.39..90.00 deg`，末端指令跨度
最大 `160.4 deg`（行程 `180 deg`），无越界。

## 启动升降回零

`Servo_Init()` 按 `SERVO_LIFT_INIT_ANGLE_DEG = 0 deg` 上电，也就是行程上端，
所以升降本来就停在停放高度上。`CraneControl_Init()` 仍在动任何驱动器之前把升降
命令到 `max_z_mm` 换算出的角度，并自行运行 `Servo_Update()` 节拍等待到位
（上限 `CRANE_LIFT_PARK_TIMEOUT_MS = 900 ms`，超时不算错误，目标保留给控制任务
的后续节拍完成）。

这一步保留是因为「舵机上电角」和「`max_z_mm` 对应的角」相等只是标定的巧合，代码
并不强制：舵机驱动只知道舵机行程，本模块才知道纸面在哪里，换算只在本模块里做。
两者若哪天不再一致，纠正就发生在这里、在动驱动器之前，而不是几秒之后——舵机只在
`Servo_Update()` 时移动，而控制任务的第一个节拍还隔着整段顶零，那几秒里电磁铁会
一直待在纸面以下，吊臂正好在上面摆动。抬升必须在顶零之前，原因同上。

停放高度同时是升降触发器和 `CraneControl_GetCurrentPose()` 的初值，因此首条轨迹
从行程上端出发，不会在开头多出一次无用的升降行程。

## 启动力矩顶零与基准

两轴目标都是绝对位置，因此驱动器的绝对坐标系必须和控制器的坐标系重合，这一点
由「在哪里清零」决定：`0xF8` 把驱动器计数清零在机构当前所在的位置上。

**不再使用驱动器自带的回零模式。** 改为力矩模式顶到机械硬限位：`0xF0` 只有方向和
电流两个参数，没有目标位置，所以电机会一直拉到被机构挡住，然后就停在那里受力。

`home_on_startup = 1` 时 `CraneControl_Init()` 的顺序是：

1. 升降抬到停放高度（见上一节），此时还没有动过任何驱动器；
2. `establish_axis_zero()` 先按「机构停在停放位姿」清零，作为顶零失败时的退路；
3. `CraneControl_Home()` **同时**给两台驱动器发力矩命令，方向都取
   `PD42S1_DIRECTION_REVERSE`，电流 `home_torque_current_ma = 400 mA`，
   持续 `home_push_ms = 3000 ms`；
4. 两轴都发零电流力矩命令结束顶零，并各发一次 `0xFB 清除状态`；
5. 清零两台驱动器（`0xF8`），此时机构停在各自的硬限位上，因此硬限位才是驱动器和
   控制器共同的位置零点；
6. 两轴各发一条**目标为 0 的绝对位置命令**（`0xF2`），把驱动器切到任务执行所用的
   模式并保持当前位置；
7. 基准取 `max_boom_yaw_deg = +90 deg` 与 `min_radius_mm = 70 mm`。

### 为什么可以两轴同时顶

顶零可以同时做，而回零（seek）不行。伸缩轴在整个过程中只会往内收，末端半径单调
减小；吊臂的硬限位在一个固定角度上，从弧线上任何位置都能顶到。也就是说「伸缩杆
必须先收回，吊臂才能转」这条机械约束，是靠**伸缩轴全程都在往内收**满足的，而不是
靠等它先到位。

### 方向与 `+90 deg` 基准

实机标定表明，1 号电机在力矩模式下发送 `PD42S1_DIRECTION_REVERSE` 会顶到吊臂局部
Yaw 的 `+90 deg` 端，因此清零后必须把该位置记为 `max_boom_yaw_deg`。运行配置的
`yaw_direction_sign = -1` 会把低于该端点的任务角转换成正的绝对位置，也就是用
`FORWARD` 离开刚才的 `REVERSE` 硬限位。若误记为 `min_boom_yaw_deg = -90 deg`，首条
任务命令会继续使用 `REVERSE`，表现为按键启动后大臂旋转方向相反。

### 第 5、6 步不可省略

第 5 步：顶零本身要走数秒，走完之后驱动器计数等于这段行程，不再是零；若只在第 2 步
清零，两个坐标系就会相差整段顶零行程，此后每条绝对目标都指向机构已经走过的位置。
绝对位置模式下这种命令会被接受但不产生任何运动，表现为伸缩轴再也收不回来。

第 6 步：驱动器的工作模式跟随最后一条运动命令，顶零之后两台都停在「通信力矩模式」。
第 5 步刚把计数清零，所以此刻「绝对位置 0」就是驱动器已经所在的位置，而手册明确说
重复发送已到达的绝对目标不产生运动——于是这条命令只切模式，机构保持在硬限位上不动。
用绝对位置而不是相对位置，是因为任务执行本身就是绝对位置模式（`send_motor_command()`），
这样切过去的模式和之后一直用的是同一个，不必让控制循环的第一条命令再切一次。

放在这里而不是交给控制循环的第一条目标去切，是为了让模式切换发生在「机构确定停在
硬限位」的时刻，而不是某次搬运的中途。

注意第 6 步依赖第 5 步：只有刚清过零，绝对位置 0 才等于当前位置。两步的顺序不能换。

任何一步失败都不会阻止启动：基准退回「机构停在停放位姿」的假设，`initialized` 仍然
置 1。这是有意的——`mission.c` 把非 OK 状态当作「机构脱离规划」并结束整轮任务，把
启动期的一次总线超时留在状态里会让第一轮在机构还没动之前就失败。真正断掉的总线会在
运行中以连续故障计数暴露出来。

`home_on_startup = 0` 时只做第 2 步，此时必须人工把 Yaw 轴放在
`startup_boom_yaw_deg = 90 deg`、伸缩轴放在 `reach_zero_radius_mm = 70 mm`。

### 为什么放弃驱动器自带的回零

驱动器的无限位回零有两个从上位机绕不过去的性质：

- 它在找到限位之后会走到一个单独的「回零零点位置」（`0x90`），出厂值是 `51200`
  即整整一圈，在伸缩轴上约 `94 mm`。这就是实测到的「伸缩杆收到底之后又往外回弹
  一小段」。把 `0x90` 设为 `0` 能消掉回弹，但——
- 它的结果只以状态码形式返回（`0x96`），而吊臂那台无论怎样调 `0x90` 和超时都始终
  没有动作，上位机除了「一直是运行中」之外拿不到任何可据以处理的信息。

力矩模式两个问题都没有：没有目标位置，就没有可以超出、退回或判失败的东西。代价是
也没有「已到位」的反馈，所以顶零只能按时间跑满（第 3 步的 `3000 ms`），提前顶到就
在硬限位上多受力一会儿。

### 力矩顶零与堵转保护

驱动器默认堵转电流是 `1500 mA`，顶零用的 `400 mA` 在它之下，所以正常顶零不会锁存
堵转保护。这是选这个电流值的原因之一：旧的无限位回零靠堵转判定到位，必然锁存保护，
而锁存住的驱动器会接受每一条运动命令却一条都不执行，还照样回复成功应答，从总线上
完全看不出异常。

顶零前后仍各发一次 `0xFB 清除状态`：前面清掉上一轮可能残留的锁存（否则顶零本身就
走不动），后面清掉这次顶零万一造成的锁存。零电流命令和 `0xFB` 都不受前面步骤失败
影响，一定会发出去，否则驱动器会一直顶着机架。

`home_torque_current_ma` 是这套方案里唯一需要实测的参数：太小则轴还没到硬限位就被
摩擦挡住，零点落在偶然的位置上；太大则整个 `3000 ms` 都在硬顶机架，并且有触发堵转
保护的风险。

限位电流是这套方案里唯一需要实测的参数：太大则轴在驱动器判定之前已经硬顶上去，
太小则轴还没到硬限位就被摩擦判成到位，零点会落在偶然的位置上。

PD42S1 当前驱动接口没有机械到位查询。命令应答只能确认驱动器已接受该目标，不能
证明机构已经到位。规划任务应在系统初始化完成后再提交有效数据，并为首次运动保留
足够的机械到位时间。

## Z 轴单次触发

升降轴不跟随规划器的连续 Z 插值。控制任务检测连续规划样本的 Z 方向：

- 首次检测到向上运动时，直接把局部 Z 目标设置为 `max_z_mm = 0 mm`（世界
  `40 mm`，舵机 `0 deg`）；
- 首次检测到向下运动时，直接把局部 Z 目标设置为 `min_z_mm = -39 mm`（世界
  `1 mm`，舵机 `149.0 deg`）；
- 同一方向持续运动时不重复设置升降舵机；
- 连续两个稳定样本后允许下一次向上或向下事件触发；
- 若工作空间或驱动调用失败，待执行命令会保留到后续样本重试。

伸缩、吊臂 Yaw 和末端 Yaw 仍按规划器参考值连续更新。规划器 Z 数值只用于
判断升降方向，不再直接换算为中间升降高度。
